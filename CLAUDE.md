# CLAUDE.md — Personal Study App (Drill)

This file is read by Claude Code at the start of every session. Follow it exactly.

## What this project is

Drill is a study app built in Claude.ai as a single HTML file. This repo moves it onto
Elisha's own PC so it runs **offline**, stores everything in a **local database**, and uses
**Qwen (via Ollama) by default, and Claude through the official Claude Code program
(`claude -p`) when online**. There is no Anthropic API key and there must never be one.

The migration must be **lossless**: every deck, concept, question, flashcard, study-guide
entry, problem course and review-schedule record that exists in Drill today must exist
afterwards, with identical content.

## Non-negotiable rules

1. **Change only the two seams.** The legacy app talks to the outside world in exactly two
   places: the storage layer (`store.get / set / delete / list`) and the AI call
   (`claudeRawCall`). Porting means replacing those two, nothing else. The slide reader,
   self-check, study modes, spaced repetition and UI stay byte-for-byte the same unless a
   phase in PLAN.md says otherwise.
2. **No data is ever deleted by code you write.** Imports merge. Migrations copy. If an
   operation would remove or overwrite existing data, stop and ask Elisha first.
3. **Verify, don't assume.** Every phase ends with its "done when" checks actually run,
   and their output shown. "It should work" is not done.
4. **Claude only through the official program.** Online requests go to the `claude`
   command in headless mode (`claude -p`). Never read, copy or reuse Claude Code's login
   token in our own code — Anthropic suspends accounts for that. No API keys.
5. **Personal data never enters the repo.** Everything lives in `DATA_DIR`. Never commit
   PDFs, databases, backups or `.env`. GitHub rejects files over 100 MB, and Module 3
   alone is 115 MB.
6. **Offline means offline.** Nothing may load from a CDN at runtime: pdf.js and fonts are
   vendored into the repo. Test with Wi-Fi off.
7. **Ask when unsure** — especially about whether something in a module is study content.
   Elisha prefers a short question over a wrong guess.

Defined in `.claude/agents/`. Use them for their phase; the reviewer checks every phase
before it is committed.

| Agent | Owns |
|---|---|
| `migration-guardian` | Getting data out of Drill and into the database with nothing lost |

| `reviewer` | Read-only check of every phase against these rules before commit |

## Commands (fill in as they are created)

- Start the app: double-click `start.bat`, or `.venv\Scripts\python -m server`
  (first time only, needs internet once: `python -m venv .venv` then
  `.venv\Scripts\python -m pip install -r requirements.txt`; after that everything runs offline)
- Run server tests: `.venv\Scripts\python -m pytest` (needs `pip install -r requirements-dev.txt`; scratch DATA_DIR only)
- Import backups: `.venv\Scripts\python -m server.importer` (server stopped; shows a plan and asks
  for `yes` before changing any existing key; `--yes` for scripts)
- Restore a snapshot: `.venv\Scripts\python -m server.restore` (lists) / `... restore <name>` (server stopped; asks for `yes`)
- Run reader tests: `npm test` (app/index.html) · `npm test -- --html legacy/drill-study-app.html` (frozen reference; fails Module 3 by design — Canva backgrounds)
- Verify an import: `.venv\Scripts\python tools\verify_import.py` (read-only; exit 0 = every row matches) ·
  Phase 7, after studying locally: `... tools\verify_import.py --after-study`
